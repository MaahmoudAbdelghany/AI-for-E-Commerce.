# AI for E-Commerce — Changelog

All notable changes to **AI for E-Commerce** are documented in this file. Format follows [Keep a Changelog](https://keepachangelog.com), and features reference [spec/roadmap.md](spec/roadmap.md).

## [Unreleased]

### Phase 3 — Arabic-First (RTL) Next.js Web Experience

Phase 3 delivers the Arabic-first (`RTL`) `Next.js 15` shopping experience where shoppers across Egypt (`EGP`), Saudi Arabia (`SAR`), and the UAE (`AED`) can choose their market, filter between `Noon` and `Amazon`, set a budget cap, and switch instantly between Arabic (`RTL`) and English (`LTR`) without reloading. Inside one unified workspace, users can converse naturally with the shopping assistant or switch to zero-LLM direct search (with optional minimum-rating and accessory filters) to compare up to three verified, server-ranked offers side by side—complete with exact decimal prices, Bayesian confidence scores, localized value reasons, cost/cache telemetry, and honest banners when matches are partial or the backend is temporarily unreachable. Known limitations: `Langfuse` trace and token-cost observability, the golden Arabic/English evaluation dataset, `Docker` containerization, distributed Redis rate limiting, and AWS deployment arrive in Phase 4 (with the two Phase 2 hardening follow-ups tracked in [`spec/backlog/2026-11-15-phase2-post-llm-and-distributed-rate-limit-followups.md`](spec/backlog/2026-11-15-phase2-post-llm-and-distributed-rate-limit-followups.md)).

#### Added
- **Feature 3.1 — Arabic-First (`RTL`) Web Shell & Market Isolation**: Launches an Arabic-default (`RTL`) `Next.js 15` storefront with instant Arabic/English (`RTL`/`LTR`) switching without page reload, country selectors (`Egypt EGP`, `Saudi Arabia SAR`, `UAE AED`), store filters (`All`, `Noon`, `Amazon`), inline-validated budget caps, a backend readiness indicator, and isolated per-country browser sessions (`localStorage`) powered by offline-safe native Arabic/English typography. ([spec](spec/features/feature-301-rtl-shell-selectors-and-api-client/plan.md))
- **Feature 3.2 — Conversational Assistant & Zero-LLM Direct Search**: Pairs natural-language Arabic/English shopping chat with a zero-LLM direct search mode (exposing optional minimum-rating and accessory controls) inside one responsive workspace featuring per-market starter prompts, a saved-offer comparison shortcut, and transparent provenance/cost telemetry (`Seed Demo` vs. `Live Search`, cache hits, LLM call counts, and filter counts). ([spec](spec/features/feature-302-chat-and-top3-comparison-experience/plan.md))
- **Feature 3.2 — Grounded Top-3 Comparison Cards & Honest Degradation**: Displays up to three verified offers in exact server-ranked order with loss-free decimal prices, customer ratings vs. explicit `Unrated` badges, Bayesian confidence scores, visual value bars, and all seven localized value reasons—while rendering accessible status and retry banners for clarifying prompts, partial (`< 3`) or empty matches, rate limits (`429`), and backend outages (`503`). ([spec](spec/features/feature-302-chat-and-top3-comparison-experience/plan.md))

#### Security
- **Feature 3.1 — Hardened Same-Origin API Proxy & Browser Headers**: Routes browser requests through runtime `force-dynamic` Next.js Route Handlers (`/api/v1/*`, `/api/health`) that enforce strict route and method allowlists, cap `POST` bodies at `64 KiB`, validate upstream JSON responses without leaking internal errors or backend host details, gate forwarded client IP headers behind an explicit trusted-proxy flag, and apply `nosniff`, anti-clickjacking (`X-Frame-Options: DENY`, `CSP frame-ancestors 'none'`), and strict referrer headers. ([spec](spec/features/feature-301-rtl-shell-selectors-and-api-client/plan.md))
- **Feature 3.2 — Safe Outbound Store Links & Refusal Privacy Hygiene**: Restricts product images and outbound store links to validated `https://` URLs (with `rel="noopener noreferrer"`, `no-referrer` image loading, safely disabled invalid CTAs, and inline fallback artwork) and ensures guardrail-refused inputs containing accidental payment or personal data are never echoed back or stored in browser session history. ([spec](spec/features/feature-302-chat-and-top3-comparison-experience/plan.md))

### Phase 2 — Bounded LangGraph Shopping Agent, Model Routing & FastAPI Service

Phase 2 turns the Phase 1 ranking engine into a conversational Arabic/English shopping assistant reachable over a documented REST API: shoppers can describe what they want in natural language, refine it over several turns, and compare saved offers, while every answer stays grounded in verified catalog data and uses at most two lightweight LLM calls per turn. The service keeps working when LLM providers, the session database, or the catalog are unavailable by falling back to rule-based parsing, ready-made bilingual templates, and in-memory sessions, and the full test suite still runs 100% offline. Known limitations: rate limiting is enforced per server process (not yet shared across multiple containers), and free-text LLM replies are not yet scanned for unverified links or prompt leakage (product offers themselves are always verified); both are tracked for Phase 4 in [`spec/backlog/2026-11-15-phase2-post-llm-and-distributed-rate-limit-followups.md`](spec/backlog/2026-11-15-phase2-post-llm-and-distributed-rate-limit-followups.md). The `Next.js` `RTL` web UI arrives in Phase 3.

#### Added
- **Feature 2.1 — Multi-Provider LLM Routing**: Lets the assistant use fast, low-cost models (`Gemini` by default with automatic one-time failover to `Groq` or `OpenAI`-compatible models) through lightweight async `httpx` adapters behind the `LLMClient` port, plus a deterministic offline `FakeLLMClient` for tests and demos. ([spec](spec/features/feature-201-llm-routing-guardrails-intent/plan.md))
- **Feature 2.1 — Bilingual Shopping Intent Understanding**: Understands Arabic (including Egyptian/Gulf phrasing and Arabic-Indic digits) and English requests—product, budget, store, minimum rating, and follow-up refinements—and falls back automatically to a built-in rule-based parser when no LLM is configured or the provider fails. ([spec](spec/features/feature-201-llm-routing-guardrails-intent/plan.md))
- **Feature 2.2 — Bounded Conversational Shopping Agent**: Answers shopping conversations through a fixed `LangGraph` flow capped at two LLM calls per turn, supports multi-turn refinements and comparisons of previously shown offers without new catalog lookups, and explains results with an LLM summary on fresh searches or a zero-cost bilingual template on cached, offline, or degraded turns. ([spec](spec/features/feature-202-langgraph-workflow-and-session/plan.md))
- **Feature 2.2 — Persistent Conversation Memory**: Remembers each shopper's recent turns and last results in `SQLite` or `PostgreSQL` (tables created automatically, atomic updates, periodic cleanup of expired sessions), switching to in-memory sessions during database outages and recovering automatically afterwards. ([spec](spec/features/feature-202-langgraph-workflow-and-session/plan.md))
- **Feature 2.3 — Versioned REST API for the Web App**: Exposes chat (`POST /api/v1/chat`), LLM-free direct search (`POST /api/v1/search`), supported markets (`GET /api/v1/markets`), and a secret-free health check (`GET /health`) with an OpenAPI 3.1 contract ready for Phase 3 TypeScript client generation, request tracing (`X-Request-ID`), and configurable CORS. ([spec](spec/features/feature-203-fastapi-service-and-contracts/plan.md))

#### Changed
- **Feature 2.1 — Smarter Catalog Caching (Phase 1 follow-ups)**: Arabic spelling variants (for example `أ`/`ا` or `ة`/`ه`) and Arabic-Indic digits now share the same cached results, budget or rating refinements reuse cached offers instead of triggering new paid searches, and simultaneous identical searches are merged into a single provider call. ([spec](spec/features/feature-201-llm-routing-guardrails-intent/plan.md))

#### Security
- **Feature 2.1 — Zero-Token Input Guardrails**: Blocks empty or oversized messages, prompt-injection and system-prompt extraction attempts (including hidden or invisible Unicode tricks), and payment cards, CVVs, passwords, or national IDs before any data is stored or any LLM is called. ([spec](spec/features/feature-201-llm-routing-guardrails-intent/plan.md))
- **Feature 2.1 — Consistent Credential Masking**: Database and cache connection passwords and API keys are now masked in every settings export and diagnostic output, and the `Gemini` key is sent only in a request header. ([spec](spec/features/feature-201-llm-routing-guardrails-intent/plan.md))
- **Feature 2.3 — Abuse Protection & Safe Error Messages**: Limits request rates per client (`429` with `Retry-After`, trusting forwarded client addresses only from configured proxies), rejects unrealistic budgets and hidden control characters, and returns one uniform error format that never exposes secrets or internal details. ([spec](spec/features/feature-203-fastapi-service-and-contracts/plan.md))

### Phase 1 — Core Foundation, Deterministic Ranking & Pluggable Catalog Layer

Phase 1 delivers the core Python backend foundation for Egypt (`EGP`), Saudi Arabia (`SAR`), and the UAE (`AED`), providing typed regional marketplace schemas (`Noon` and `Amazon`), deterministic Top-3 value scoring with Bayesian rating confidence and two-stage bilingual anti-accessory/price-outlier filtering, offline bilingual seed catalogs, live single-call Serper Shopping integration, and bounded in-memory LRU plus Redis TTL caching. Known limitations: this release provides a headless Python foundation only—`LangGraph` natural-language orchestration and `FastAPI` HTTP endpoints arrive in Phase 2, the `Next.js` `RTL` web UI arrives in Phase 3, and three minor cache and settings improvements are tracked in [`spec/backlog/2026-11-15-phase1-cache-and-settings-followups.md`](spec/backlog/2026-11-15-phase1-cache-and-settings-followups.md).

#### Added
- **Feature 1.1 — Regional Marketplace Schemas & Configuration**: Ensures shoppers and downstream services receive consistent local marketplace data across Egypt (`EG` / `EGP`), Saudi Arabia (`SA` / `SAR`), and the UAE (`AE` / `AED`) with `Decimal` price precision (`0.01`), strict market-to-currency pairing, typed error classes, and standardized domain models (`ProductOffer`, `SearchIntent`, `RankedOffer`, `RankingResult`, `CatalogSearchResult`, and `MARKET_REGISTRY`). ([spec](spec/features/feature-101-backend-scaffold-domain-models/plan.md))
- **Feature 1.1 — Hexagonal Backend Scaffold & Typed Settings**: Gives developers and operators a dependency-locked Python `3.11+` backend workspace (`backend/pyproject.toml`, `backend/uv.lock`), `.env`-backed runtime and scoring configuration (`AppSettings`, `ScoringConfig` with `top_k` `1..3`), canonical bilingual cache-key formatting (`SearchIntent.normalized_cache_key()`), and pure domain isolation free of vendor SDK imports (`commerce_ai.config`, `commerce_ai.domain`). ([spec](spec/features/feature-101-backend-scaffold-domain-models/plan.md))
- **Feature 1.2 — Deterministic Top-3 Value Scoring Engine**: Gives shoppers reproducible, zero-token Top-3 product recommendations (`rank_top_offers` in `commerce_ai.domain.ranking`) combining normalized price (`0.55`) and Bayesian confidence-adjusted ratings (`0.45`, prior count `25`, prior mean `4.0`) to eliminate 1-review 5-star traps, apply a conservative `3.4` fallback for unrated listings, attach grounded `match_reasons`, and report partial pools honestly (`degraded_fewer_than_k=True`). ([spec](spec/features/feature-102-deterministic-value-ranking/plan.md))
- **Feature 1.2 — Two-Stage Bilingual Anti-Accessory & Price-Outlier Filter**: Protects search results from cheap accessories and distorted pricing by running a Stage 1 Arabic/English semantic-concept filter (6 concept groups honoring explicit accessory queries and `include_accessories=True`) before a Stage 2 `Decimal` median floor (`< 0.15x` median) and ceiling (`> 3.0x` median unless accommodated by `max_budget`) outlier guard at `3+` candidates. ([spec](spec/features/feature-102-deterministic-value-ranking/plan.md))
- **Feature 1.3 — Pluggable Catalog Ports & Resilient TTL Caching**: Speeds up repeat searches and protects external search budgets through abstract `CatalogProvider` and `CacheStore` protocols (`commerce_ai.domain.ports`), a bounded `InMemoryTTLCache` (`OrderedDict` LRU, `max_entries=1024`), an async `RedisCacheStore` (verified offline with `fakeredis`), automatic fallback to in-memory caching when Redis is unset or unreachable, and `CachedCatalogProvider` graceful degradation without caching provider failures. ([spec](spec/features/feature-103-pluggable-catalog-and-cache/plan.md))
- **Feature 1.3 — Bilingual Regional Seed Catalogs (`EG`, `SA`, `AE`)**: Enables 100% offline testing and deterministic demos via `SeedCatalogProvider` and versioned Arabic/English seed datasets (`seeds/eg.json`, `seeds/sa.json`, `seeds/ae.json`) spanning 5+ categories across `Noon` and `Amazon` with built-in accessory, 1-review 5-star, unrated, and `4x` scalper traps. ([spec](spec/features/feature-103-pluggable-catalog-and-cache/plan.md))
- **Feature 1.3 — Single-Call Live Serper Shopping Integration & Honest Runtime Mode**: Supports live regional `Noon` and `Amazon` offer discovery via `SerperShoppingProvider` capped at one async request per cache miss (`num=40`, `2.0s` timeout, `~$0.001` per miss, zero scraping) alongside an honest `auto` / `seed` / `serper` catalog factory that raises typed `CatalogProviderError` instead of disguising seed items as live results. ([spec](spec/features/feature-103-pluggable-catalog-and-cache/plan.md))

#### Security
- **Verified Regional Store & Attributed Google Shopping URLs**: Enforces `https://` links restricted to official regional `Noon` (`noon.com/egypt*`, `noon.com/saudi*`, `noon.com/uae*`) and `Amazon` (`amazon.eg`, `amazon.sa`, `amazon.ae`) stores—or Google Shopping product links paired with explicit regional `Noon`/`Amazon` merchant attribution—rejecting cross-country (`amazon.com`) and third-party sellers across both direct validation and JSON cache deserialization (`CachedCatalogProvider` explicit context). ([spec](spec/features/feature-101-backend-scaffold-domain-models/requirements.md))
- **Malformed & Traversal URL Payload Rejection**: Enforces strict `HttpUrl` parsing across offer and `image_url` fields while blocking control characters, whitespace, embedded `user:pass@` credentials, backslashes, semicolons, and raw or percent-encoded path traversal segments (`.`, `..`, `%2e`, `%2f`, `%5c`, `%3b`). ([spec](spec/features/feature-101-backend-scaffold-domain-models/requirements.md))
- **Credential Masking & PII-Free Boundaries**: Masks `SERPER_API_KEY` (`SecretStr`) and `REDIS_URL` passwords or query secrets across `AppSettings` string/diagnostic outputs (`repr()`, `str()`, `safe_summary()`), cache factory fallback warnings, `RedisCacheStore` exceptions (`CacheStoreError`), and `SerperShoppingProvider` error reasons (`CatalogProviderError`), while excluding all payment and sensitive PII fields from domain schemas (`INV-01`, `INV-09`). ([spec](spec/phases/phase-1-core-foundation/phase-review.md))
