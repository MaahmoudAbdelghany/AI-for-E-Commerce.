# Requirements: Feature 2.2 — Bounded LangGraph Shopping Agent Workflow & Async Session Memory

> Decisions and behaviours, not implementation micro-details. Every requirement must be testable and map to at least one check in `validation.md`.

## 1. Functional Requirements

| ID | Requirement | Validated by (validation.md check) |
|:---|:---|:---|
| **R1** | `InMemorySessionStore` (`backend/src/commerce_ai/adapters/session/memory.py`) must implement `SessionRepository` (`clock: Callable[[], float] \| None = None`, `max_sessions: int = 1024`, `max_turns: int = 10`), rejecting non-positive `max_sessions` or `max_turns < 2`, guarding mutations with `asyncio.Lock`, expiring entries deterministically by monotonic TTL (with `ttl_seconds <= 0` removing/skipping storage), pruning expired entries before LRU eviction at capacity, trimming `turns` to the most recent `max_turns`, returning defensive deep copies from `get_session()`, and performing idempotent `delete_session()`. | `T1.1`, `T3.1` |
| **R2** | `SQLAlchemySessionRepository` (`backend/src/commerce_ai/adapters/session/sqlalchemy_repo.py`) must implement `SessionRepository` via async `SQLAlchemy 2.0` (`AsyncEngine`, `async_sessionmaker`) supporting both `sqlite+aiosqlite` (with `timeout=3.0`, WAL on file-backed DBs, and `busy_timeout=5000`) and `postgresql+asyncpg` (`timeout=2.0`, `command_timeout=5.0`), define the `commerce_sessions` table (`session_id`, `market`, `payload_json`, `expires_at_epoch`, `updated_at_epoch`), provide `async def initialize() -> None` using `Base.metadata.create_all` (zero `backend/migrations/**` files) and `async def close() -> None`, upsert atomically via dialect-native `ON CONFLICT DO UPDATE` with throttled expired-row cleanup (`<= 1` per `60.0s`), trim `turns` to `max_turns`, preserve previously verified Google Shopping HTTPS URLs in `last_ranked_offers` via `SessionState.model_validate_json(..., context={"allow_verified_google_shopping_from_cache": True})`, enforce `expires_at_epoch` expiration on reads, and raise `SessionStoreError` on DB or corrupt-JSON/`InvalidOperation` failures. | `T1.2`, `T2.1`, `T3.2` |
| **R3** | `create_session_repository(settings: AppSettings)` (`backend/src/commerce_ai/adapters/session/factory.py`) must synchronously construct and return `ResilientSessionRepository` implementing `SessionRepository`, `async def initialize() -> None`, `async def close() -> None`, `backend_name: Literal["sqlite", "postgresql", "memory"]`, and `is_degraded: bool`, resolving `backend_name="sqlite"` (`is_degraded=False`) for `sqlite+aiosqlite` and `backend_name="postgresql"` (`is_degraded=False`) for `postgresql+asyncpg`, permanently degrading and safely closing `_primary` on startup `initialize()`/URL failures, and degrading with a configurable `30.0s` cooldown recovery probe (isolating non-transient per-row corrupt data errors) on runtime `SessionStoreError` (`INV-08`). | `T1.3`, `T3.3` |
| **R4** | `commerce_ai.agent.prompts` must expose `build_explanation_request(...) -> LLMRequest` for bounded Call #2 explanation/comparison (`max_tokens <= 300`), embedding strictly verified `RankedOffer` facts (`rank`, `offer_id`, `title`, `price`, `currency`, `store`, `rating`, `review_count`, `value_score`, `bayesian_rating`, `match_reasons`, `url`), delimiting offer titles as untrusted data, reflecting `degraded_fewer_than_k` honest partial counts when `< top_k`, and instructing the model in Arabic (`ar`) or English (`en`) never to invent or modify prices, ratings, review counts, or URLs (`INV-05`). | `T1.4` |
| **R5** | `commerce_ai.agent.templates` must expose zero-token deterministic Arabic (`ar`) and English (`en`) template builders covering: Top-K recommendation summary (using only verified `RankedOffer` facts, `INV-05`), 0-offer empty result notice (`INV-08`), partial `< top_k` (`degraded_fewer_than_k=True`) honest notice (`INV-08`), saved-offers side-by-side comparison (`COMPARE` fallback), `CLARIFY` question (including missing saved offers for `COMPARE`), `OFF_TOPIC` polite redirect, `REFUSED` guardrail notice (echoing zero PII/injection payloads, `INV-09`), and `DEGRADED` catalog outage message (`INV-08`). | `T1.5` |
| **R6** | `ShoppingAssistantWorkflow` (`backend/src/commerce_ai/agent/graph.py`) must accept `(settings: AppSettings, catalog_provider: CatalogProvider, session_repository: SessionRepository, llm_client: LLMClient \| None = None, scoring_config: ScoringConfig \| None = None)`, compile a `LangGraph` `StateGraph` containing nodes `guard -> load_session -> parse -> route -> [respond_guard_or_clarify \| fetch_catalog -> rank_offers -> explain \| compare_saved -> explain] -> save_session -> END`, and expose `async def run_turn(self, *, message: str, session_id: str \| None = None, default_country: CountryCode = CountryCode.EG, store_override: StoreFilter \| None = None, max_budget_override: Decimal \| None = None, language_hint: Literal["ar", "en"] \| None = None) -> ChatTurnResult`. | `T1.6`, `T2.1` |
| **R7** | On guardrail failure (`check_input_guardrails(..., max_chars=settings.guardrail_max_chars)` returning `allowed=False`), the `guard` node must short-circuit directly to `respond_guard_or_clarify -> END` returning `ChatTurnResult(status=TurnStatus.REFUSED, action=TurnAction.REFUSE, top_offers=[], ...)` with `0` `LLMClient` calls, `0` `CatalogProvider` calls, and `0` `SessionRepository` reads or writes, leaving any pre-existing session state untouched (`INV-09`). | `T1.7`, `T2.3` |
| **R8** | `load_session` and `parse` must generate a UUID4 `session_id` when omitted, fetch existing `SessionState` via `SessionRepository.get_session()`, and pass `prior_intent=state.last_intent`, up to the last `6` compact `SessionTurn` entries (`recent_turns`), and `has_saved_offers=bool(state.last_ranked_offers)` into `extract_turn_intent(...)`, enabling budget, store, and country refinements (*"أرخص تحت ٢٠٠٠"*, *"بدّل للسعودية"*, *"من نون بس"*) to merge onto `last_intent` and hit `CachedCatalogProvider` (`catalog_cache_key()`) when upstream query/store/country/language are unchanged. | `T1.8`, `T2.1`, `T2.2` |
| **R9** | When `route` receives `TurnAction.COMPARE`, it must execute `compare_saved -> explain` strictly against `state.last_ranked_offers` with **0 `CatalogProvider` calls** (`telemetry.catalog_called=False`) when saved offers exist, and otherwise transition cleanly to `TurnAction.CLARIFY` (`TurnStatus.CLARIFY`) via `respond_guard_or_clarify` asking the user to search for a product first. | `T1.9`, `T2.2`, `T3.8` |
| **R10** | `ShoppingAssistantWorkflow` must strictly enforce `telemetry.llm_calls <= 2` per user turn (`0–1` in `parse`, at most `1` in `explain`) with zero autonomous retry loops across all `explain_mode` settings (`INV-04`). | `T1.10`, `T3.9` |
| **R11** | In `explain`, when `settings.explain_mode == "auto"`, the workflow must execute grounded Call #2 (`max_tokens <= 300`) **only** when `llm_client is not None` AND `len(offers) > 0` AND no `llm_provider_error:` occurred in Call #1 AND `(action == TurnAction.COMPARE or not catalog_cache_hit)`, and otherwise render via `templates.py` (`telemetry.used_template_summary=True`, `0` tokens) on catalog cache hits, offline runs (`llm_client is None`), `0` offers, `explain_mode == "template"`, Call #1 `LLMProviderError` fallback, or Call #2 `LLMProviderError`/empty-response fallback (`INV-08`); in `explain_mode == "llm"`, it runs Call #2 whenever `llm_client is not None` and `len(offers) > 0` within `llm_calls <= 2`. `ChatTurnResult.top_offers` must always come strictly unmodified from `rank_top_offers` or `state.last_ranked_offers` (`INV-05`). | `T1.10`, `T1.11`, `T2.1`, `T3.4` |
| **R12** | `ShoppingAssistantWorkflow` must degrade gracefully (`INV-08`): `CatalogProviderError` during `fetch_catalog` returns `ChatTurnResult(status=TurnStatus.DEGRADED, top_offers=[], ranking_result=None, ...)` with localized template reply (`used_template_summary=True`) and sanitized `telemetry.degraded_reason`; `0` qualifying offers or `1–2` partial offers (`degraded_fewer_than_k=True`) return honest localized notices with zero fabricated padding (`INV-05`). | `T3.4`, `T3.5`, `T3.7` |
| **R13** | `save_session` must update `last_intent` and `last_ranked_offers` on successful `SEARCH` turns, preserve prior `last_intent` and `last_ranked_offers` intact across `COMPARE`, `CLARIFY`, `OFF_TOPIC`, and `DEGRADED` turns, append user/assistant `SessionTurn` records trimmed to `settings.session_max_turns` (`10`), persist with `settings.session_ttl_seconds`, and catch `SessionStoreError` during `load_session` or `save_session` cleanly without failing the user response (`INV-08`). | `T1.12`, `T3.6`, `T3.8` |

## 2. Non-Functional Requirements

| ID | Requirement (performance budget, security, privacy, cost, accessibility, i18n…) | Validated by (validation.md check) |
|:---|:---|:---|
| **NFR1** | **Secret & Credential Redaction (`INV-01`)**: `SQLAlchemySessionRepository`, `ResilientSessionRepository`, and `ShoppingAssistantWorkflow` must never hardcode credentials or expose `database_url` passwords/tokens or API keys inside logs, `SessionStoreError`, `TurnTelemetry.degraded_reason`, or `ChatTurnResult.reply` (always scrubbing via `redact_url_password`). | `T3.3`, `T3.6` |
| **NFR2** | **Strict Hexagonal Isolation (`INV-02`)**: `commerce_ai.agent.{prompts,templates,graph}` must import zero vendor HTTP/DB/LLM SDKs (`httpx`, `redis`, `sqlalchemy`, `aiosqlite`, `asyncpg`, `serper`, `langfuse`, `boto3`, `openai`, `litellm`, `google`, `groq`) or `commerce_ai.adapters.*`, relying exclusively on `CatalogProvider`, `LLMClient`, and `SessionRepository` protocols. | `T1.13`, `T5.1`, `T5.3` |
| **NFR3** | **Cached Latency & Token Cost Budget (`spec/mission.md` §4, §6, `INV-04`)**: Cached repeat and refinement turns under `explain_mode="auto"` must execute `0` Call #2 LLM tokens and `0` upstream catalog requests, completing within the `<= 300 ms` P95 cache-hit target (`< 300 ms` CI wall-clock assertion using offline adapters and disk SQLite). | `T2.2`, `T3.10` |
| **NFR4** | **100% Offline Deterministic Verification (`INV-07`)**: All unit and integration checks in `test_session_stores.py`, `test_agent_graph.py`, and `test_langgraph_session.py` must pass 100% offline in `< 30 s` without external databases, network sockets, or paid API keys. | `T2.1`, `T2.4`, `T3.10`, `T4.1` |
| **NFR5** | **Code Quality, Strict Static Typing & Disjoint Partition (`spec/sdd-profile.md`, `P7`)**: Feature 2.2 source and tests must pass `ruff check .`, `ruff format --check .`, `mypy src`, and `uv lock --check` cleanly without modifying `pyproject.toml`, `uv.lock`, `__init__.py` scaffolds, or Feature 2.1/2.3 files. | `T4.1`, `T5.1`, `T5.2`, `T5.3`, `T5.4` |

## 3. Constraints (must NOT do / change)

- **C1 (`INV-01`)**: Must NOT log, embed, or return raw `DATABASE_URL` passwords, query secrets, or API keys in exceptions, telemetry, or responses.
- **C2 (`INV-02`)**: Must NOT import `httpx`, `sqlalchemy`, `aiosqlite`, `asyncpg`, `redis`, `serper`, `langfuse`, `openai`, `litellm`, or `commerce_ai.adapters.*` inside `commerce_ai/agent/{prompts,templates,graph}.py`.
- **C3 (`INV-04`, `INV-05`)**: Must NOT execute more than 2 LLM calls per turn, perform ranking math inside LLM prompts, or fabricate/modify `RankedOffer` fields (`top_offers`).
- **C4 (`INV-09`)**: Must NOT persist guardrail-blocked messages (payment cards, CVV, passwords, national IDs, prompt injections) into `SessionRepository` or echo blocked secrets back in refusal messages.
- **C5 (`P7`, Sensitive Areas)**: Must NOT create `backend/migrations/**` files or modify `backend/pyproject.toml`, `backend/uv.lock`, package `__init__.py` scaffolds, `config/`, `domain/`, `adapters/{catalog,cache,llm}/`, `agent/{guardrails,intent}.py`, `main.py`, `api/`, or `tests/integration/test_phase2_e2e.py`.
