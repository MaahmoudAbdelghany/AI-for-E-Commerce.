# Requirements: Feature 3.2 — Interactive Shopping Chat & Top-3 Comparison Experience

> Status: Draft (Pending Phase Gate 1 Approval)
> Decisions and behaviours, not implementation micro-details. Every requirement is testable and maps bidirectionally to checks in [validation.md](validation.md).

## 1. Functional Requirements

| ID | Requirement | Validated by (`validation.md` check) |
| :--- | :--- | :--- |
| **R1** | `frontend/src/app/page.tsx` MUST render `<ShoppingWorkspace />` inside Feature 3.1's `<AppShell>`, consuming `useShopSession()` (`country`, `store`, `maxBudget`, `parsedMaxBudget`, `budgetError`, `language`, `activeMarketSession`, `appendMarketTurn`, `setActiveComparison`, `resetActiveMarketSession`, `t`) in a responsive RTL-first 2-column desktop layout (`lg:grid-cols-12`, conversation/search pane + sticky Top-3 comparison grid) and stacked mobile layout (`375px` width) with a quick-jump `#comparison-panel` trigger when comparison data exists and zero horizontal overflow. | `T2.5`, `T6.1`, `T6.2`, `T7.1` |
| **R2** | `ModeToggle.tsx` MUST provide an accessible bilingual segmented control switching inside the unified workspace between **Conversational Assistant (`POST /api/v1/chat`, default)** and **Zero-LLM Direct Search (`POST /api/v1/search`, `0` LLM calls)** while preserving the active market's `sessionId`, message history, and `ActiveComparisonState`. | `T2.1`, `T2.2`, `T6.1` |
| **R3** | In **Zero-LLM Direct Search** mode, `MessageComposer.tsx` and `ShoppingWorkspace.tsx` MUST expose a query input (validated inline as trimmed non-empty `1..500` chars without disallowed control/bidi/Tag chars matching `SearchRequest`), an optional `min_rating` (`0..5`) selector, and an `include_accessories` checkbox, binding `country`, `store`, `language`, and validated `parsedMaxBudget` from `useShopSession()`, calling `searchOffers(...)` (`0` LLM calls), and updating the unified `ActiveComparisonState` (`mode: "search"`, `queryLabel: response.intent.query`, `rankedOffers: response.ranking_result.ranked_offers`, `rankingResult: response.ranking_result`, `sourceMode: response.source_mode`, `cacheHit: response.cache_hit`, `llmCalls: 0`, `latencyMs: response.latency_ms`, `requestId: response.request_id`, `status: "search_ok"`). | `T2.2`, `T3.1`, `T7.1` |
| **R4** | `ChatThread.tsx` MUST render the active market's bilingual message history (`ChatMessageItem[]`) with localized sender labels, mixed-script RTL/LTR text isolation (`dir="auto"`), per-turn assistant `action`/`status` metadata badges, an accessible loading skeleton/indicator while a turn is in flight, empty-state guidance when no messages exist, and jsdom-safe auto-scroll to new messages without hijacking keyboard focus. | `T2.1`, `T2.4`, `T3.2`, `T6.1` |
| **R5** | In **Conversational Assistant** mode, `MessageComposer.tsx` MUST provide a localized Arabic/English placeholder, submit on `Enter` (preserving `Shift+Enter` newlines) or Send button click, disable/guard submissions while `isSubmitting === true` to prevent duplicate requests, check `budgetError` / `validateBudgetInput(maxBudget)` inline (`> 0` and `<= 10,000,000.00`) blocking API calls with a `role="alert"` error when invalid, and render a **"قارن أفضل العروض / Compare Saved Offers"** quick-action button visible ONLY when `(activeMarketSession.activeComparison?.rankedOffers.length ?? 0) >= 2`, dispatching a `POST /api/v1/chat` comparison turn (`TurnAction.COMPARE`) on click. | `T2.1`, `T2.3`, `T3.1`, `T3.2`, `T6.1` |
| **R6** | `StarterPrompts.tsx` MUST display localized per-market (`EG`/`SA`/`AE`) and per-language (`ar`/`en`) clickable example queries from `STARTER_PROMPTS` (`src/lib/i18n.ts`) aligned with seeded and live catalog categories (such as Anker earbuds, air fryer, and iPhone 15), dispatching a chat search turn when clicked and remaining disabled while `isSubmitting === true`. | `T2.1`, `T2.4`, `T6.1` |
| **R7** | `ProductComparisonGrid.tsx` MUST render `1–3` `RankedOffer` cards strictly in server-returned order (`rank: 1..3`) with ZERO client-side re-sorting, price math, or synthetic placeholder items (`INV-03`, `INV-05`), handling `compare` responses (`rankingResult: null`) and partial `< 3` results (`1–2` cards) cleanly. | `T1.4`, `T2.1`, `T2.2`, `T2.3`, `T3.4` |
| **R8** | `OfferCard.tsx` MUST display for each `RankedOffer`: rank badge (`#1`, `#2`, `#3`), localized store badge (`نون / Noon`, `أمازون / Amazon`), verified `offer.title`, exact string-preserved `offer.price` + `offer.currency` via `formatExactPrice`, raw `rating` + `review_count` via `formatRatingValue` (or explicit `"غير مُقيّم / Unrated"` badge when `offer.rating === null \|\| offer.review_count === 0`), `bayesian_rating` (`formatBayesianScore`, `X.XX / 5.0`), visual `value_score` progress bar (`formatValueScore`, `XX.X / 100`, `role="progressbar"`), and localized `match_reasons` pills covering all 7 `MatchReasonCode` values (`best_overall_value`, `lowest_price`, `top_bayesian_rating`, `high_review_confidence`, `within_budget`, `unrated_fallback`, `strong_value_runner_up`) from `MATCH_REASON_LABELS` (`src/lib/i18n.ts`). | `T1.1`, `T1.2`, `T2.4` |
| **R9** | `OfferCard.tsx` MUST enforce strict `https://` URL validation via `sanitizeHttpsUrl` (`src/lib/format.ts`, `INV-05`, `INV-09`): render `<img loading="lazy" referrerPolicy="no-referrer">` ONLY for validated `https://` `image_url` values and switch cleanly to an inline SVG product icon fallback when `image_url` is `null`, fails validation, or fires `onError`; and render outbound store CTAs as `<a href={safeHttpsUrl} target="_blank" rel="noopener noreferrer">` while safely disabling the CTA (without an unsafe `href`) if `offer.url` fails `sanitizeHttpsUrl`. | `T1.3`, `T6.1` |
| **R10** | `TelemetryStrip.tsx` MUST display `sourceMode` (`بيانات تجريبية / Seed Demo` vs `بحث مباشر / Live Search`, or a saved-offer comparison indicator when `sourceMode === null`), `cacheHit` (`Cache Hit` vs `Miss`), `llmCalls` (`0` for `/search`, `0–2` for `/chat`), formatted `latencyMs` (`formatLatencyMs`), `requestId`, and `rankingResult` filter counts (`total_candidates`, `filtered_accessories_count`, `filtered_outliers_count`) when available. | `T1.5`, `T2.1`, `T2.2`, `T2.3` |
| **R11** | `StatusBanner.tsx` MUST render distinct, accessible bilingual notices (`role="status"` for informational/partial outcomes; `role="alert"` for errors/refusals) across all non-nominal states: `clarify`, `off_topic`, `refused` (without echoing sensitive/PII input), `degraded` (`CatalogProviderError` in chat), partial `< 3` results (`degraded_fewer_than_k === true` alongside the `1–2` verified cards and zero fake padding), `0` qualifying offers (clearing stale comparison cards), HTTP `429` (`Retry-After` seconds + retry guidance), and HTTP `503`/network failure with a working Retry button that re-submits the failed request. | `T1.6`, `T3.3`, `T3.4`, `T3.5` |
| **R12** | `ShoppingWorkspace.tsx` MUST preserve strict per-market isolation (`EG`/`SA`/`AE`) and mid-flight consistency: switching `country` or clicking "New Chat" during an in-flight request cancels/ignores stale responses so offers and turns never bleed across markets; `clarify`, `off_topic`, and `refused` responses leave prior valid `activeComparison` offers intact; and `ChatResponse(status="refused")` masks/redacts rejected sensitive user input before saving turns to `localStorage` (`INV-09`). | `T2.4`, `T3.2`, `T3.3` |

## 2. Non-Functional Requirements

| ID | Requirement | Validated by (`validation.md` check) |
| :--- | :--- | :--- |
| **NFR1** | **Deterministic Grounding & Zero Client Math (`INV-03`, `INV-05`)**: Workspace components MUST NEVER compute or alter `price`, `value_score`, `bayesian_rating`, or card ordering client-side, and MUST render zero synthetic placeholder offers when `< 3` offers match. | `T1.1`, `T1.2`, `T1.4`, `T3.4` |
| **NFR2** | **Link, Image & PII Privacy Security (`INV-09`)**: All outbound links MUST enforce strict `https://` validation + `rel="noopener noreferrer"`; unsafe `image_url`/`url` protocols (`http:`, `javascript:`, `data:`, credentials) MUST be blocked; guardrail-refused PII/payment inputs MUST NEVER be echoed in `StatusBanner` or persisted raw into `localStorage`. | `T1.3`, `T1.6`, `T3.3` |
| **NFR3** | **Bilingual Accessibility & Responsive RTL/LTR Layout (`spec/mission.md` §7)**: All interactive controls, status banners (`role="status"`/`role="alert"`), tabs (`role="tablist"`), and score bars (`role="progressbar"`) MUST carry accessible bilingual (`ar`/`en`) labels, mixed-script `dir="auto"` content hygiene, desktop 2-column layout (`1280px`), and zero horizontal overflow on `375px` mobile viewports. | `T1.1`, `T1.6`, `T2.4`, `T6.1`, `T6.2` |
| **NFR4** | **100% Offline Deterministic Tests & Build (`INV-07`)**: All unit and integration tests MUST run offline via Vitest + React Testing Library mocking `api.ts` / `fetch` with zero live network calls, and `next build` MUST execute offline with zero `next/font/google` imports. | `T1.1`–`T3.5`, `T4.1`, `T5.3` |
| **NFR5** | **Strict Type Safety, Linting & Cross-Stack Regression (`spec/sdd-profile.md`)**: All authored workspace components, `src/app/page.tsx`, and test files MUST pass `npm --prefix frontend run lint`, `npm --prefix frontend run typecheck` (`strict: true`, `noUncheckedIndexedAccess: true`), `npm --prefix frontend run build`, and keep `uv run --no-sync --directory backend pytest -v` 100% green. | `T4.1`, `T4.2`, `T5.1`, `T5.2`, `T5.3`, `T7.1` |

- **C2 (`INV-07`)**: MUST NOT import `next/font/google` or invoke live external HTTP/LLM/Serper endpoints during Vitest unit/integration runs.
- **C3 (`INV-03`, `INV-05`, `INV-09`)**: MUST NOT sort, filter, recalculate, or synthesize `RankedOffer` items client-side, MUST NOT render unsafe non-`https://` links or `<img>` sources, and MUST NOT introduce checkout, payment, or authentication UI.
- **C4 (`spec/sdd-profile.md`)**: MUST NOT touch Sensitive Areas (`infra/aws/**`, `.github/workflows/**`, `backend/src/commerce_ai/config/security*`, `backend/migrations/**`).

## 4. Dependencies & Assumptions

- **Depends on**:
  - **Feature 3.1 (must be implemented and committed locally on `phase/3-rtl-web-experience` before Feature 3.2 implementation starts)**: `frontend/package.json`, `frontend/package-lock.json`, `frontend/vitest.config.ts`, `frontend/tests/setup.ts`, `frontend/src/lib/{contracts,api,i18n,format,storage}.ts`, `frontend/src/context/ShopSessionContext.tsx`, `frontend/src/components/shell/AppShell.tsx`, `frontend/src/app/{layout.tsx,globals.css,page.tsx}`, and `frontend/src/app/api/**`.
  - **Phase 2 Backend Service (done)**: `POST /api/v1/chat`, `POST /api/v1/search`, `GET /api/v1/markets`, and `GET /health` in `backend/src/commerce_ai/api/routes.py` & `schemas.py`.
  - **Environment variable names only (`INV-01`)**: `BACKEND_API_URL` (server-side proxy default `http://127.0.0.1:8000`) and optional `NEXT_PUBLIC_API_BASE_URL` (handled inside Feature 3.1's `api.ts` and Route Handlers).
- **Assumptions**:
  - Feature 3.1 pre-declares all workspace bilingual dictionary keys (including all 7 `match_reasons`, `TurnStatus`, telemetry labels, error banners, and per-market starter prompts) in `frontend/src/lib/i18n.ts`, and pre-defines `ChatMessageItem` and `ActiveComparisonState` in `frontend/src/lib/contracts.ts`, so Feature 3.2 consumes them read-only without touching `src/lib/*`.
  - `OpenJS.NodeJS.LTS` (`node` and `npm`) is installed on the workstation prior to Phase 3 implementation (`P2`).
